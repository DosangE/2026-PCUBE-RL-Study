# 리더보드 운영 (운영진용)

채점은 **참가자 로컬 Unity에서 전부 끝납니다.** 서버(= 구글 폼 + 시트)가 하는 일은 제출된 결과를 모아 **순위를 매기는 것뿐**이고, 점수를 다시 계산하지 않습니다.

```
참가자 로컬 Unity                        구글 폼 / 시트
─────────────────                        ──────────────
10개 환경 동시 주행
  봇(고스트) → T_baseline
  에이전트    → T_agent
ScoreAggregator → 총점        ──POST──>  디코드 → 체크섬 확인 → 정렬 → Leaderboard 시트
[결과 제출] 버튼
```

제출은 **Unity가 폼의 `formResponse` 엔드포인트로 직접 POST**합니다. 참가자는 버튼만 누르고, 복사·붙여넣기 단계가 없습니다.

---

## 1. 폼 만들기

Google Form을 새로 만들고 질문 2개를 둡니다.

| 질문 | 유형 | 비고 |
|---|---|---|
| GitHub ID | 단답형 | 참고용 (실제 순위는 코드 안의 ID를 씁니다) |
| **제출 코드** | **장문형** | `RBC1:` 로 시작하는 한 줄. 반드시 장문형이어야 잘리지 않습니다 |

응답을 스프레드시트에 연결합니다 (응답 탭 → 스프레드시트에 연결).

**두 가지를 반드시 확인하세요.**

1. **익명 응답 허용** — 설정에서 "응답자 이메일 수집"과 "조직 내 사용자로 제한"을 모두 끕니다. 켜져 있으면 Unity의 POST가 로그인 페이지로 튕겨 조용히 버려집니다.
2. **필드 id 확보** — 폼 미리보기를 열고 페이지 소스에서 `entry.` 를 검색하면 질문마다 하나씩 나옵니다.

### Unity 쪽 설정

`Assets/RacingBotCup/Config/SubmissionConfig.asset` 을 열고 세 칸을 채운 뒤, 이 에셋이 포함된 상태로 스타터 킷을 배포합니다.

| 칸 | 값 |
|---|---|
| Form Url | `https://docs.google.com/forms/d/e/<FORM_ID>/formResponse` (주소창이 아니라 **소스에서** 복사) |
| Participant Entry Id | GitHub ID 질문의 `entry.xxxxx` |
| Payload Entry Id | 제출 코드 질문의 `entry.xxxxx` |

## 2. 스크립트 설치

1. 연결된 스프레드시트에서 **확장 프로그램 → Apps Script**
2. `Code.gs` 내용을 붙여 넣기
3. 상단 설정값을 실제 폼에 맞게 수정:

```js
var RESPONSE_SHEET = '설문지 응답 시트1';   // 실제 응답 시트 이름
var CODE_COLUMN_HEADER = '제출 코드';        // 제출 코드 질문 제목
var CHECKSUM_SALT = 'RacingBotCup/2026/score-v2';  // Unity 쪽과 동일해야 함
```

`Code.gs` 와 Unity의 `SubmissionCodec.cs` 는 **한 쌍으로 움직입니다.** 체크섬을 만드는 정규화 문자열이 바뀌면 salt 끝의 `-vN` 도 같이 올라가니, 둘 중 하나만 갱신하면 모든 제출이 `⚠ 체크섬 불일치` 로 떨어집니다. 스타터 킷을 새로 배포할 때는 시트의 스크립트도 같이 붙여 넣으세요.

4. 트리거 추가: **트리거 → 트리거 추가 → `onFormSubmit` / 스프레드시트에서 / 양식 제출 시**

수동으로 돌리려면 시트 메뉴의 **RacingBot Cup → 리더보드 다시 만들기**를 쓰면 됩니다.

## 3. 동작 방식

- 참가자당 **가장 좋은 제출 하나**만 남깁니다. 여러 번 내도 불이익이 없습니다.
- 정렬 순서는 기획서 §6과 같습니다: **총점 → 완주율 → 점수 표준편차(작을수록 위)**
- `무결성` 열이 `OK`가 아니면 그 제출은 살펴볼 값어치가 있다는 뜻입니다.
- `에이전트` 열에는 채점에 쓰인 `프리팹/모델` 이름이 그대로 남습니다. 결선에서 같은 모델이 왔는지 대조할 때 씁니다.

---

## 무결성 열을 어떻게 읽을 것인가

`⚠ 체크섬 불일치`는 **부정의 증거가 아닙니다.** 다음 중 어느 것이든 이 표시가 납니다.

- 폼 질문이 단답형이라 코드가 잘림 (장문형으로 바꾸세요)
- 참가자가 구버전 프로젝트로 채점
- `CarSpec` · `RaceRules` · `ScoreAggregator` 를 수정한 채 실행
- `CHECKSUM_SALT` 가 Unity 쪽과 다르게 설정됨 (운영진 실수)
- 시트의 `Code.gs` 가 배포된 스타터 킷보다 오래됨 (운영진 실수 — 위 §2 참고)

먼저 **다시 제출하도록 요청**하세요. 그래도 어긋나면 `무결성` 열 옆의 해시들을 비교해 어떤 모듈이 다른지 특정할 수 있습니다.

### 솔직하게 말하면

클라이언트에서 계산한 결과는 **원리적으로 위조 가능합니다.** 체크섬 salt는 모든 참가자가 실행하는 빌드 안에 그대로 들어 있으므로, 마음먹은 사람은 체크섬까지 다시 만들 수 있습니다. 이 장치의 목적은 **실수와 가벼운 손질을 눈에 띄게 하는 것**이지 막는 것이 아닙니다.

이번 대회는 그 위에 **신뢰를 전제로** 운영합니다. 실질적인 검증 장치는 하나뿐입니다:

> **결선은 운영진이 비공개 트랙에서 직접 돌립니다** (기획서 §8).

기간 중 리더보드는 연습 사다리이고, 진짜 승부는 결선입니다. 참가 안내에도 이 프레이밍을 그대로 써 두었습니다.

### 고정 공개 시드에 대해

평가 시드 10개는 공개되어 있고 대회 내내 바뀌지 않습니다. 즉 **그 10개 트랙에 과적합하는 것이 가능합니다.** 로컬 채점을 택한 이상 시드를 숨기는 것은 불가능하므로(참가자가 직접 실행해야 하니까), 이를 감추는 대신 드러내 놓고 운영합니다. 세트를 10개로 넉넉히 잡은 것은 과적합의 비용을 올리기 위한 것이고, 일반화 여부는 결선 OOD 트랙에서 갈립니다.
