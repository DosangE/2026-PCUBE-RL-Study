# week6 — RacingBot Cup 기획서

> **한 줄 요약**: 동일한 차량·동일한 트랙 생성기 위에서, 참가자가 각자 설계한 ML-Agents 자율주행 에이전트로 **처음 보는 트랙을 얼마나 빠르고 안정적으로 도는지** 겨루는 솔로 타임어택 대회.

---

## 1. 왜 이 대회인가

week1~5에서 배운 것(관측 설계 · 보상 설계 · 하이퍼파라미터 · 센서 선택)을 **한 문제에 전부 쏟아붓는** 종합 과제입니다. 특히:

- **일반화**가 곧 점수 — 특정 트랙에 과적합하면 처음 보는 트랙에서 무너집니다
- **설계의 자유도가 곧 실력차** — 차량 물리는 모두 같으므로, 순위는 "무엇을 보게 했는가 / 무엇을 잘했다고 알려줬는가"에서 갈립니다
- 리더보드가 있으므로 **실험 → 측정 → 개선** 사이클을 자기 주도로 돌게 됩니다

## 2. 경기 개요

| 항목 | 내용 |
|---|---|
| 종목 | 솔로 타임어택 (차량 간 상호작용·추월·충돌 없음) |
| 차량 | 운영진 제공 `CarController` 1종 고정 (물리·성능 전원 동일) |
| 트랙 | 시드 기반 절차적 생성 (`TrackGenerator`) |
| 참가자가 만드는 것 | `RacerAgent` 상속 클래스 + 센서를 붙인 **프리팹** + 학습된 `.onnx` 모델 |
| 평가 | 공개 시드 10개를 **동시에** 주행 → 베이스라인 봇 대비 랩타임 |
| 기간 중 | 로컬에서 채점 → 버튼 한 번으로 제출 → 리더보드 반영 |
| 결선 | 제출 마감 후, 완전 비공개 트랙에서 최종 주행 → 우승자 결정 |

## 3. 고정되는 것 vs 자유인 것

대회의 뼈대입니다. **"차는 똑같고, 뇌만 다르다"**.

| 영역 | 고정 (운영진 제공) | 자유 (참가자 설계) |
|---|---|---|
| 차량 물리 | 질량·엔진 토크·조향각·마찰·다운포스 | — |
| 행동 공간 | 연속 2차원 `[steer, throttle]` (`-1~1`) 또는 제공된 이산 매핑 | 둘 중 택 1 |
| 트랙 생성 | 생성기 알고리즘·난이도 파라미터 범위 | 학습에 쓸 시드·난이도 조합 |
| **관측** | — | **전부 자유.** 센서 컴포넌트도, `CollectObservations` 코드도 직접 씁니다 (4절) |
| **보상** | — | **전부 자유** |
| **학습** | — | 알고리즘(PPO/SAC), 하이퍼파라미터, 커리큘럼, 학습 스텝, 네트워크 구조 전부 자유 |
| 추론 | ONNX + 인엔진 추론, 결정론 모드 | — |

> 보상과 학습 설정은 **학습 시점에만 존재**하고 평가에 개입하지 않으므로 제약이 전혀 없습니다.
> 관측도 4절에서 보듯 완전 자유입니다 — 고정되는 것은 차량 물리와 행동 공간뿐입니다.

## 4. 관측 — 완전 자유, API로 제공

> **원안에서 바뀐 부분입니다.** 처음에는 `obs_config.json` 스키마로 센서를 조립하는 **관측 카탈로그** 방식이었습니다. 평가 하네스가 남의 코드를 컴파일하지 않아도 되게 하려는 장치였는데, 채점이 참가자 로컬로 옮겨간 시점에 그 전제가 사라졌습니다 — 어차피 각자 자기 빌드를 돌립니다. 카탈로그를 걷어내고 **API**로 바꿨습니다.

### 참가자가 만드는 것

`RacerAgent`를 상속한 클래스 하나와, 그것이 붙은 **프리팹** 하나입니다.

```csharp
public class MyRacer : RacerAgent
{
    public override void CollectObservations(VectorSensor sensor)
    {
        sensor.AddObservation(Car.ForwardSpeed / 50f);
        sensor.AddObservation(Projection.Lateral / (Projection.Width * 0.5f));
        sensor.AddObservation(WaypointLocal(20f).x / 50f);
        sensor.AddObservation(CurvatureAhead(30f) * 30f);
        // 원하는 만큼, 원하는 대로
    }

    protected override void OnDriveApplied(float steer, float throttle)
    {
        AddReward(...);   // 보상도 전부 자유
    }
}
```

레이·카메라·그리드 센서는 **인스펙터에서 컴포넌트로 붙입니다.** ML-Agents가 알아서 수집하므로 개수·각도·거리·해상도에 제한이 없습니다.

### 베이스 클래스가 열어 주는 것

| 프로퍼티 / 메서드 | 내용 |
|---|---|
| `Car` | 속도·로컬 속도·각속도·조향각·슬립각·이탈 바퀴 수 |
| `Projection` | 센터라인 부호거리 · 트랙 폭 · 곡률 · 도로 위 여부 |
| `WaypointLocal(m)` | m 앞 센터라인 지점을 차 기준 좌표로 |
| `CurvatureAhead(m, window)` | 전방 구간 평균 곡률 |
| `SectionAhead(m)` | 다음 구간의 **타입** (직선/코너/헤어핀/시케인/에세스) 과 브레이킹 존 여부 |
| `Checkpoints`, `LapProgress`, `TimeSinceCheckpoint`, `IsOffTrack` | 랩 진행 상태 |

카탈로그에 있던 항목은 전부 여기 있고, **없던 것도 씁니다** — 예를 들어 "다음 코너가 헤어핀인가"는 카탈로그로는 표현할 수 없던 관측입니다.

### 고정되는 것

행동 공간만 고정입니다: **연속 2차원 `[steer, throttle]`(-1~1)** 또는 **이산 2브랜치(조향 5 × 스로틀 3)**. BehaviorParameters에 어느 쪽이든 선언하면 베이스 클래스가 차에 매핑합니다.

상한 검증은 없습니다. 레이를 500개 쏘면 **본인 평가만 느려질 뿐** 남에게 피해가 가지 않으므로 제약하지 않습니다.

## 5. 트랙 생성기 스펙 — F1 스타일 섹션 조합

`com.unity.splines` 기반. 무작위 곡선이 아니라 **이름 있는 섹션의 시퀀스**로 서킷을 씁니다.

### 섹션 어휘

| 타입 | 성격 |
|---|---|
| `Straight` | 전개 구간. 최고속에 도달할 만큼 길다 (실측 170~375 m) |
| `Corner` | 리프트 없이 도는 스위퍼 |
| `Hairpin` | 랩에서 가장 느린 지점. 반경 14~19 m |
| `Chicane` | 짧은 구간의 좌-우 급전환 |
| `Esses` | 모멘텀을 이어가는 연속 코너 |

**헤비 브레이킹 존**은 별도 타입이 아니라 **헤어핀/시케인 직전 직선에 붙는 표시**입니다. `TrackSection.IsBrakingZone`으로 조회할 수 있고, 문법이 이 조합을 보장합니다.

### 생성 절차

1. 시드 → **모티프 문법**으로 섹션 시퀀스 결정 (`[직선, 헤어핀]`처럼 짝으로 뽑아 브레이킹 존이 우연이 아니라 구조적으로 생기게 함)
2. 섹션별 가중치로 원형 링 위 앵커 배치 — **닫힘이 구성적으로 보장**됨
3. 섹션마다 센터라인을 **해석적으로 조밀 폴리라인**(7 m 간격)으로 그림 — 직선은 공선점, 헤어핀은 실제 원호, 시케인·에세스는 사인 곡선
4. 이음매 평활화 → 스플라인 knot으로 투입
5. **섹션 타입별** 최소 반경 검증 + 자기근접 검증 → 실패 시 다른 레이아웃으로 재시도
6. 도로 메시 + 커브(kerb) + 그래블 런오프 + 체크포인트 생성

> knot을 몇 개만 놓고 AutoSmooth에 맡기면 헤어핀에서 무너집니다. AutoSmooth는 이웃까지의 거리로 탄젠트를 정하므로, 40 m 직선이 8 m 원호와 만나는 지점에서 긴 쪽이 오버슛해 **2 m 첨점**을 만듭니다. 몇 m 간격의 조밀한 knot은 보간이 지어낼 여지를 남기지 않습니다.

### 난이도 파라미터 (시드로 샘플링되는 범위)

| 파라미터 | 범위 | 비고 |
|---|---|---|
| 총 길이 | 800 ~ 2,000 m | 섹션 수가 길이에 비례 (7~14) |
| 트랙 폭 | 8 ~ 12 m | 시케인이 성립하려면 6 m는 너무 좁음 |
| 최소 곡률 반경 | 22 ~ 38 m | 헤어핀·시케인은 별도 하한(11 m) |
| 고저차 | 0 | v2에서 도입 검토 |

### 트랙 밖

**물리적 벽은 두지 않습니다.** 트랙 밖은 마찰이 절반 이하인 **그래블 런오프**(코스 양쪽 9 m) — 나가면 느려지는 것이 자연스러운 페널티가 되고, "벽에 비비면서 코너 도는" 꼼수도 원천 차단됩니다. 트랙 양쪽 가장자리에는 빨강·흰색 **커브(kerb)** 가 한 바퀴 전 구간에 깔려 노면 경계가 눈으로 읽힙니다 (커브 폭 1.4 m 중 안쪽 0.3 m만 트랙, 바깥 1.1 m는 이탈로 계산). 런오프 바깥은 초록 잔디입니다.

노면·런오프 머티리얼은 PolygonStreetRacer 에셋에서 가져옵니다. 커브와 스타트/피니시 체커는 그 텍스처 좌하단의 색상 스와치를 UV로 찍어 같은 머티리얼 하나로 처리합니다. 잔디와 타이어 자국은 에셋에 없어 코드로 생성합니다 (`Assets/RacingBotCup/Materials`).

### 도메인 랜덤화 (일반화 유도)

- **시각**(카메라 관측자용): 시간대·조명·건물 배치·노면 텍스처를 시드로 변경
- **물리**(옵션): 그립·질량 ±5% — 도입 시 **평가에서도 시드로 고정**해 결정론 유지

## 6. 평가 방식

### 주행 규칙

| 항목 | 규칙 |
|---|---|
| 랩 | 스탠딩 스타트 후 1랩 |
| 체크포인트 | 순서대로 전부 통과해야 랩 인정 (역주행·숏컷 차단) |
| 이탈 | 4륜이 트랙 밖인 상태가 **3초 지속되면 DNF** |
| 구조/리셋 | 없음. 나가면 스스로 복귀 |
| 타임아웃 | 베이스라인 봇 타임 × 3 |

### 점수

트랙 `t` 하나에 대해:

```
S_t = clamp(T_baseline / T_agent, 0, 2.0)      # 완주 시
S_t = 0                                         # DNF / 타임아웃
```

**총점 = 모든 트랙 `S_t`의 평균.**

- `T_baseline` = 운영진 제공 **규칙 기반 봇**(센터라인 추종 + 곡률 기반 감속)의 해당 트랙 기록
- 트랙 난이도가 자동 정규화되고, **`S = 1.0`이 "봇과 동급"** 이라는 직관적 기준선이 생깁니다
- DNF가 0점이므로 **"빠르지만 가끔 터지는" 정책보다 안정적인 정책이 유리** → 일반화 유도

**동점 처리**: ① 완주율 → ② 트랙별 점수 표준편차가 작은 쪽

### 결정론 확보 (같은 제출은 항상 같은 점수)

- `Time.fixedDeltaTime = 0.02` 고정, 트랙 생성에 전용 PRNG 사용(`UnityEngine.Random` 금지), 추론 `deterministic = true`
- **의사결정 주기도 고정**(4스텝 = 80ms) — 학습과 평가의 주기가 다르면 같은 정책이 다르게 주행합니다
- 평가 루프는 `Physics.Simulate` 로 직접 스텝합니다. 관측 → 판단 → 힘 적용 → 적분 순서가 고정되어 컴포넌트 실행 순서에 결과가 좌우되지 않고, 실시간보다 훨씬 빠릅니다
- 서로 다른 PC 간 완전 일치는 PhysX 부동소수점 때문에 보장되지 않습니다. 점수가 **같은 PC에서 잰 봇 대비 비율**이라 이 차이는 대부분 상쇄됩니다
- ~~`-nographics` 카메라 이슈~~ — 로컬 채점으로 바뀌면서 헤드리스 실행 자체가 없어져 해당 없음

## 7. 리더보드 — 로컬 채점 + 서버 랭킹

> **원안에서 바뀐 부분입니다.** 처음에는 운영진 서버가 비공개 시드로 제출물을 평가하는 구조였지만,
> **채점 전부를 참가자 로컬 Unity에서 수행**하고 서버는 순위만 매기는 방식으로 변경했습니다.
> 구현은 `week6/RacingBotCompetition/Assets/RacingBotCup/` 에 있습니다.

### 흐름

```
참가자 로컬 Unity                          구글 폼 / 시트
─────────────────                          ──────────────
시드마다  봇 주행 → T_baseline
          에이전트 주행 → T_agent
ScoreAggregator → 총점
SubmissionCodec → "RBC1:..."   ──POST──>  디코드 → 체크섬 확인 → 정렬 → 리더보드
       [결과 제출] 버튼
```

제출물은 `.onnx` 파일이 아니라 **한 줄짜리 제출 코드**이고, **버튼이 구글 폼의 `formResponse` 엔드포인트로 직접 POST**합니다 — 복사·붙여넣기도, 서버도 없습니다. 서버는 점수를 재계산하지 않습니다.

### 이 변경이 없앤 것들

- 평가 빌드를 돌릴 **CI 인프라가 통째로 불필요**해졌습니다 (self-hosted runner / xvfb / GPU 러너 선택 문제 소멸)
- `-nographics` 에서 카메라 센서가 검게 나오는 문제도 사라져 **카메라 센서를 제약 없이 허용**할 수 있습니다
- `T_baseline` 을 같은 PC에서 즉석으로 재므로 **기준선 테이블 배포가 불필요**하고, 점수가 비율이라 **하드웨어 격차가 대부분 상쇄**됩니다

### 이 변경이 만든 대가

시드는 **고정 공개 세트 10개**입니다 (`Assets/RacingBotCup/Config/eval_seeds.json`). 채점이 참가자 PC에서 도는 이상 시드를 숨길 방법이 없으므로, 숨기는 대신 드러내 놓고 운영합니다.

즉 **평가 트랙에 과적합하는 것이 가능합니다.** 이를 감수하는 대신:

- 기간 중 리더보드는 **연습 사다리**로 규정합니다 (실시간 순위 경쟁이 아님)
- **결선(8절)이 유일한 실질 검증**입니다 — 운영진이 비공개 트랙에서 직접 실행
- 시드를 10개로 넉넉히 잡아 과적합 비용을 올립니다

| 시드 대역 | 용도 | 공개 |
|---|---|---|
| `0 ~ 99,999` | 학습·연습용 | 공개 |
| `eval_seeds.json` 10개 | 리더보드 | **공개** |
| 별도 | 결선 | 비공개 |

### 무결성 — 신뢰 모델

제출 코드에는 점수 외에 `CarSpec` · `RaceRules` · `ScoreAggregator` · `TrackGenerator` 의 해시와, 어떤 프리팹·모델이 그 점수를 냈는지가 함께 들어갑니다. 어긋나면 시트에 `⚠` 로 표시됩니다.

단, 이것은 **변조 방지가 아니라 변조 흔적**입니다. 클라이언트에서 계산한 결과는 원리상 위조 가능하고, 체크섬 솔트도 빌드 안에 들어 있습니다. 이 대회는 그 위에 **참가자가 채점 모듈을 수정하지 않는다는 신뢰**를 전제로 운영하며, 실질적 방어선은 결선 하나입니다.

### 제출 규격

제출 코드 외에, 심사(효율상·설계상)용으로 다음을 PR로 남깁니다.

```
week6/submissions/<github-id>/
├── MyRacer.cs           # RacerAgent 상속 클래스
├── configuration.yaml   # 학습 설정
└── meta.json            # 총 스텝, 학습 시간, 하드웨어, 한 줄 설명
```
